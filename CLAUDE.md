Контекст: ученик Makar Urvantsev, PASCAL Private Secondary School Lemesos, Year 1 / класс 1B, 2026–27. Владелец — Igor (родитель). Общение с пользователем и тексты баз знаний — на русском; оригиналы сообщений не переводить.

## Структура (не менять без запроса)
- `Messages/` — оригиналы. `Messages/index.md` — индекс (`| datetime | source | topic | link |`, новые сверху).
  - `Messages/mail/` — письма Gmail от Pascal + `attachments/`.
  - `Messages/edu portal/` — сообщения портала простым списком (без папок по учителям) + `attachments/`.
  - В `Messages/mail/` и `Messages/edu portal/` есть подпапка `DONE/` для обработанных пользователем сообщений (статус = нахождение в `DONE/`, в имени статуса нет).
- `Files/` — важные долгоживущие вложения, актуальные весь год. Новая версия заменяет старую. ДЗ/временное — не сюда.
- `<YYYY-MM-DD> KNOWLEDGE BASE/` — вся актуальная информация (индивидуальная включительно). Дата = последняя суммаризация.
- `<YYYY-MM-DD> PUBLIC/` — только общее для школы и 1B, без индивидуальных данных. Дата = последняя суммаризация.

## Правила
1. Имена сообщений: Gmail — `<YYYY-MM-DD> <TOPIC>.md`; портал — `<TEACHER> <YYYY-MM-DD HH-MM> <NAME>.md` (`TEACHER` = `Фамилия Имя`, в начале имени). Статуса в имени нет: статус «обработано» определяется только тем, что файл лежит в папке `DONE/`; новые сообщения всегда создаются в корне `Messages/mail/` или `Messages/edu portal/`.
2. Вложения сообщения — кликабельная ссылка на файл в `attachments` источника (Gmail: относительная `attachments/…`; портал: `[[Messages/edu portal/attachments/…|…]]`). Не дублировать вложения между источниками без причины; не перезаписывать существующие файлы.
3. Диалоги можно объединять в один файл по теме.
3а. Перемещение сообщений в `DONE/` — **только по запросу пользователя** (skill `/pascal-done`: показывает чек-лист всех сообщений не из `DONE/`, по умолчанию все отмечены; после подтверждения переносит выбранные в `DONE/` и обновляет все ссылки). Новые сообщения никогда не кладутся в `DONE/`; имя файла при переносе не меняется.
3б. Сообщения в `DONE/` участвуют в анализе наравне с остальными: при чтении, дедупликации, суммаризации и сверке баз знаний агент обращается к ним точно так же (искать рекурсивно: `Messages/mail/**`, `Messages/edu portal/**`).
4. Дедупликация: Gmail — `gmail_id` во frontmatter; портал — `teacher` + `date` во frontmatter (по всем файлам, включая `DONE/`). Индекс обновлять при каждом добавлении сообщения.
5. Базы знаний правятся прямо в основном тексте, **без** `==…==`; устаревшее исправлять/удалять; обновлять `updated:` во frontmatter и срез в README (00). После суммаризации переименовать обе папки на сегодняшнюю дату и поправить ссылки.
6. KNOWLEDGE BASE и PUBLIC должны соответствовать друг другу и актуальным сообщениям; PUBLIC не содержит индивидуальную часть (профиль ученика, оплаты, отсутствия/здоровье, документы, пароли). Общие школьные файлы для PUBLIC копируются в `PUBLIC/attachments/`.
7. Приватность: не переносить в базы содержимое паспортов, медицинских данных, сертификатов, паролей, номеров документов; не отправлять данные вовне.
8. Ссылки — wikilinks от корня хранилища (`[[Messages/…|…]]`); пути, начинающиеся с цифры/«-», в shell брать в кавычки или с `./`.
9. Не удалять пользовательские файлы без явной просьбы; удаление разрешено только для заменяемых устаревших версий в `Files/` и технического мусора.

## Обновление проекта
Используй skill `/pascal-update` (`.claude/skills/pascal-update/SKILL.md`): Gmail + портал edu4schools (браузер, залогиниться просит пользователя), Messages → index → Files → KB/PUBLIC → сверка → отчёт в диалог на русском (письма: найдено/новые/уже были; скачанные сообщения портала; суммаризация изменений).
