# /pascal-done — перенос обработанных сообщений в DONE/

Запускается **только по явному запросу пользователя**. Статус сообщения определяется только тем, лежит ли файл в подпапке `DONE/` (в имени статуса нет). Без подтверждения пользователя ничего не переносится.

Хранилище (по умолчанию `/Users/igor.urvantsev/obsidian/prv/Pascal-Limassol`, в `device_bash` — `$HOME/mnt/Pascal-Limassol`) находи по шагу A. Перенос — это `mv` внутри хранилища, удаление не требуется.

## Шаг A. Найти хранилище (выполнить первым)
1. Вызови `get_device_info` (`mcp__remote-devices__get_device_info`; если инструмент отложен — загрузи через ToolSearch) и посмотри `connectedFolders`. Хранилище — папка, где лежат `CLAUDE.md`, `README.md` и `Messages/` (обычно `Pascal-Limassol`; проверь через `device_list_dir`). В `device_bash` оно доступно как `$HOME/mnt/<имя папки>` — дальше везде используй этот путь.
2. Если такой папки среди подключённых нет — запроси доступ: `device_request_folder_access` для `/Users/igor.urvantsev/obsidian/prv/Pascal-Limassol` (подтверждение появится на компьютере) и повтори шаг 1.
3. Если инструменты `mcp__remote-devices__*` недоступны или компьютер не отвечает — не пытайся работать в облаке и не ищи файлы в контейнере: сообщи пользователю, что сессия не привязана к его компьютеру (или он недоступен), и остановись.

## Шаги
1. **Получи список.** Возьми все файлы `*.md`, лежащие непосредственно в `Messages/mail/` и `Messages/edu portal/` (не в подпапке `DONE/` и не в `attachments/`). Если список пуст — сообщи «все сообщения уже в DONE/» и закончи.
2. **Пришли чек-лист** пользователю в диалог, на русском: два раздела (`mail`, `edu portal`), новые сверху (по дате в имени файла), нумерация сквозная. **По умолчанию все сообщения отмечены** — строки вида `N. [x] <имя файла без .md>` (для читаемости можно добавить дату и тему). Предложи переместить их в `DONE/` и объясни: чтобы оставить сообщение на месте, пользователь называет его номер («снять 3, 7»); «всё» или «да» — переместить все отмеченные; «отмена» — ничего не перемещать. `AskUserQuestion` годится для общего решения (`переместить все` / `снять часть` / `отмена`; не больше 4 вариантов), номера для снятия принимай текстом.
3. **Дождись ответа пользователя.** Без явного подтверждения ничего не перемещай. Подтверждение действует только на этот запуск.
4. **Перенеси выбранные** (все, кроме снятых пользователем). Создай при необходимости `Messages/mail/DONE/` и `Messages/edu portal/DONE/`. Для каждого: старый путь `OLD` (без `.md`, от корня хранилища, например `Messages/edu portal/Stephanou Andreas 2026-10-09 07-07 Title`) и новый `NEW` (`Messages/edu portal/DONE/Stephanou Andreas 2026-10-09 07-07 Title`). **Имя файла не меняется.** Используй `mv -n`; если в `DONE/` уже есть файл с таким именем — остановись для этого файла и спроси пользователя.
5. **Относительные ссылки в письмах.** У писем Gmail (`Messages/mail`) ссылки на вложения в теле относительные: при переносе в `DONE/` замени `](attachments/` на `](../attachments/` в самом перенесённом файле. У сообщений портала ссылки на вложения абсолютные (`[[Messages/edu portal/attachments/…]]`) — не трогать.
6. **Обнови ссылки** на перенесённые сообщения **во всех `.md` хранилища** (кроме `.git`, `.obsidian`, `.claude`): `Messages/index.md`, обе базы знаний (`<дата> KNOWLEDGE BASE`, `<дата> PUBLIC`), README и другие сообщения. Замена строкой `OLD` → `NEW` для wikilinks `[[OLD|…]]`, `[[OLD\|…]]`, `[[OLD]]` и markdown-ссылок (с `%20` вместо пробелов, если встречаются). Делай python-скриптом (read-modify-write) по словарю `{OLD: NEW}` — не вручную.
7. **Проверка:** все wikilinks в `Messages/index.md`, `Messages/**/*.md` и базах знаний указывают на существующие файлы; перенесённых файлов нет в корне `Messages/mail` и `Messages/edu portal`; во frontmatter ничего менять не нужно.
8. **Отчёт** пользователю на русском: сколько и какие сообщения перенесены (источник, имя), сколько оставлено на месте по просьбе пользователя, в скольких файлах обновлены ссылки, найденные проблемы.

Замечания: сообщения в `DONE/` остаются полноправными источниками для анализа и дедупликации (`/pascal-update` ищет рекурсивно). Обратный перенос (вернуть из `DONE/` в корень) — только по явной просьбе пользователя, теми же шагами в обратном направлении (в письмах `](../attachments/` → `](attachments/`).
